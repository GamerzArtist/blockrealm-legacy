## 2026-08-06 - Strict Content Security Policy and Android WebView Domain Locking
**Vulnerability:** Surprising security gap in this app's architecture where there was no restriction on the domains loaded/redirected in the Android WebView (allowing arbitrary web loading/phishing risks), and a complete lack of a Content Security Policy (CSP) in the frontend application allowing arbitrary script execution or resource injection if XSS is present.
**Learning:** In hybrid mobile voxel apps where JavaScript is enabled, the lack of `shouldOverrideUrlLoading` on the `WebViewClient` allows the main frame or sub-frames to navigate to external malicious pages, which would run with access to DOM storage and local assets. Additionally, dynamically generated textures (e.g., pixel canvases converted to `data:` URIs via `toDataURL()`) require a carefully designed CSP containing `img-src 'self' data: blob:` to avoid breaking client-side rendering.
**Prevention:** Always restrict WebView navigation using modern and deprecated `shouldOverrideUrlLoading` overloads to only trusted origins like `https://appassets.androidplatform.net/`. Additionally, specify a highly restrictive CSP meta tag `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; manifest-src 'self'; connect-src 'self'; media-src 'self' blob: data:;` to prevent inline script execution and unauthorized remote script loads.
