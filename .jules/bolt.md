## 2026-08-10 - Bounded Procedural Terrain Cache
**Learning:** In procedural voxel games, generating terrain columns repeatedly during chunk creation, decoration, player spawning, and height calculations causes massive computational overhead due to recursive FBM (Fractal Brownian Motion) and Value Noise functions. Implementing a `terrainCache` Map drastically reduces recalculation from hundreds of calls per chunk to just 1 per column coordinate, bringing a near-100% hits-rate for redundant queries. Furthermore, to avoid JS engine performance degradation, clearing the Map completely using `.clear()` when reaching its 10,000 bounds is significantly faster and less resource-intensive than manual FIFO iterator-based deletions.
**Action:** Always implement a bounded Map cache for procedurally generated noise functions in performance-critical paths, and clear the Map completely via `.clear()` rather than using Map iterator/FIFO deletions to avoid garbage collection and iterator overhead.
