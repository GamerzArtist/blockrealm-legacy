## 2026-08-08 - Bounded Map Caching for Procedural Terrain Info
**Learning:** Generating procedural terrain columns on-the-fly (e.g., via fbm octaves of valueNoise) is highly intensive and frequently queried redundantly (e.g. during decoration or surface checks). Implementing a Map-based terrain cache provides significant speedups, but cache eviction inside hot-paths using manual FIFO iterator deletions (e.g. `Map.prototype.keys().next().value`) causes high engine overhead due to iterator allocations. Clearing the Map completely using `.clear()` when bounds are reached completely avoids this penalty and keeps JS performance extremely fast.
**Action:** Always use bounded Map caches that clear entirely via `.clear()` rather than utilizing incremental FIFO iterator evictions inside performance-critical, hot paths. Clear the cache whenever the world state or world seed updates to prevent stale cache entries.
